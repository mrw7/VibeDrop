## 二、关键问题清单

### 🔴 Critical

#### C0: .env.local 和 .env.example 包含真实密钥
- **影响**: 阿里云 OSS AccessKey、GitHub OAuth secret 等真实凭证暴露在仓库中
- **立即行动**: 轮换所有暴露的密钥，将 `.env.local` 加入 `.gitignore`

#### C0.2: `fflate` 被引用但未在 package.json 中声明
- **文件**: `src/app/api/apps/[id]/deploy/route.ts`
- **影响**: 部署到生产环境时运行时崩溃
- **行动**: 添加 `fflate` 到 `dependencies` 或移除引用

#### C1: 零测试覆盖
- **影响**: 重构无安全网，回归风险高
- **PRD 要求**: Vitest 单元/集成测试 + Playwright E2E
- **建议**: 先加 Playwright smoke test（登录→浏览→发布→播放），再加 Vitest

#### C2: shadcn/ui 未安装（PRD 明确要求）
- **影响**: PRD Implementation Decisions 要求 "TailwindCSS with shadcn/ui"，但完全未初始化
- **后果**: Button、Card、Dialog、Select 全是手写，缺少 Radix 无障碍模式（focus trap、键盘导航、aria 属性）
- **建议**: `npx shadcn@latest init` → 逐步迁移基础组件

#### C3: 无运行时输入校验（Zod）
- **影响**: Server Actions 直接信任客户端输入，可能有注入/恶意数据
- **文件**: 所有 `actions.ts`、API routes
- **建议**: 引入 Zod schema 校验所有 Server Action 入参和 API body

### 🟡 High

#### H0: crypto-js (~500KB) 可用 Node 内置 crypto 替代
- **文件**: `src/lib/encryption.ts`
- **影响**: 服务端代码不需要浏览器端加密库，`node:crypto` 零依赖
- **建议**: 用 `crypto.createCipheriv` / `createDecipheriv` 替换 CryptoJS

#### H1: 错误处理不一致 + 客户端静默吞错
- **现状**: `throw new Error("Unauthorized")` → 无统一错误码，前端只能 catch 字符串
- **建议**: 定义 `AppError` 类，含 `code` + `status` + `message`，前端集中处理

#### H2: 无 CSP / 安全 Header
- **影响**: XSS 风险，iframe 内容未受 Content-Security-Policy 限制
- **文件**: `next.config.ts` 缺失 headers 配置
- **建议**: 添加 CSP header，限制 iframe 中可加载的资源源

#### H3: Prisma N+1 查询
- **文件**: `apps/[id]/page.tsx` — comments 的 user 通过 include 加载（OK），但 like 状态另查一次
- **建议**: 合并查询或用 Prisma 的 `interactiveTransactions`

#### H5: Like/Unlike 竞态条件
- **文件**: `src/app/apps/[id]/actions.ts`
- **影响**: check-then-act 模式（`findUnique` → `create`/`delete`） + 分离的计数器增减，并发请求会导致 `likesCount` 错误
- **建议**: 用 Prisma 事务或 `upsert` 原子化操作

#### H6: 数据库缺少显式索引
- **影响**: `App.authorId`、`App.buildStatus`、`Comment.appId`、`Build.appId` 等频繁查询列无索引
- **建议**: 在 `prisma/schema.prisma` 中添加 `@@index`

#### H7: 无连接池 / 查询超时
- **风险**: 生产环境数据库连接耗尽
- **建议**: 配置 Prisma connection_limit + 查询超时

### 🟠 Medium

#### M1: 没有 loading/empty/error 三态统一模式
- **现状**: 部分页面有 loading.tsx（刚加），但 client component 中没有统一的 state machine
- **建议**: 创建 `useAsyncAction` hook 封装 loading/error/data 三态

#### M2: 硬编码的 OSS URL 格式
- **文件**: `src/lib/oss.ts` — `getOSSUrl` 硬编码 URL 模板
- **建议**: 使用 OSS SDK 的 `generateObjectUrl` 或配置化

#### M3: 排序算法在应用层计算
- **文件**: `apps/page.tsx` — 全量查出 → 内存排序，数据量大时性能差
- **建议**: 使用 PostgreSQL 表达式或物化视图

#### M4: 无 API 速率限制
- **风险**: 恶意刷点赞/评论
- **建议**: 添加 `rateLimit` middleware

#### M5: `src/app/metadata.ts` 存在但未使用
- **文件**: `src/app/metadata.ts` — 定义了全局 metadata，但 `layout.tsx` 里又写了一份

### 🟢 Low

#### L1: 冗余 SVG inline
- 多处重复的内联 SVG（搜索图标、心形图标等）
- **建议**: 提取为 `components/icons.tsx`

#### L2: 暗色模式无系统跟随
- ThemeToggle 有初始化检测，但切换系统主题时不会自动更新
- **建议**: 监听 `matchMedia('prefers-color-scheme')` change 事件

#### L3: 无 PWA / Service Worker
- 可以加 `next-pwa` 支持离线访问
